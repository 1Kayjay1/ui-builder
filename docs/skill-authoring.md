# Skill authoring

Workflow skills are compact decision procedures, not encyclopedias. Each `SKILL.md` should state activation criteria, the workflow, deterministic tools to use, relevant knowledge modules, completion criteria, and stop conditions.

Keep durable design theory in `assets/knowledge/`. A form-polish task should not load shader or 3D material unless the task actually needs it. New skills must preserve the central boundary: judgment belongs in skills; measurement, filesystem work, parsing, and browser inspection belong in tools.
