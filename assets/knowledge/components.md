# Components

Prefer native semantics, then accessible/headless primitives for complex behavior, then vetted visual components, then custom code. Own visuals through project tokens. Expose meaningful variants rather than arbitrary CSS props. Think semantic element → accessibility/input primitive → state logic → visual tokens → animation → product composition. Preserve the project's controlled/uncontrolled and framework conventions. Registry discovery must consider framework, dependencies, license, accessibility, performance, visual fit, and canonical source.
